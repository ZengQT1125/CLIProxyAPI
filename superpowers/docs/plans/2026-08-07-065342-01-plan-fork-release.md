# CLIProxyAPI Fork Release

**Goal:** Publish the current `main` revision through a new annotated `fork/v*` tag on the fork repository.
**Why planning is required:** Creating and pushing a release tag mutates public remote state and triggers GitHub Actions.
**Acceptance:** The worktree is clean; the release level is derived from every non-merge commit since the latest `fork/v*` tag; the new tag matches `fork/vX.Y.Z` and is absent locally and remotely; the verified release-candidate HEAD is tagged; `main` and the tag are pushed to `origin`; remote refs and the workflow trigger are inspected. Stop without overwriting tags, rewriting history, or pulling/rebasing after a push failure. If the push fails before the tag is published, delete only the newly created local tag. If a wrong tag is published, recovery is limited to deleting that exact remote and local tag.

### Outcome 1: Release version is derived from complete fork history
- Work: Identify the latest `fork/v*` tag, inspect every following non-merge commit, and apply the highest semantic-version impact defined by the release workflow.
- Risks/open questions: Upstream `v*` tags must not influence the fork version.
- Verify: `git describe --tags --match "fork/v*" --abbrev=0` and `git log <previous-tag>..HEAD --no-merges`

### Outcome 2: The verified revision is published without overwriting remote state
- Work: Reuse fresh code verification for the unchanged code tree, verify local and remote tag absence, create an annotated `fork/v*` tag, and push the current branch plus that tag to `origin`.
- Risks/open questions: A concurrent publisher may create the tag after preflight; any failure must preserve the branch and avoid force-push or implicit reconciliation.
- Verify: `git ls-remote origin refs/heads/main refs/tags/<new-tag> refs/tags/<new-tag>^{}`

### Outcome 3: Release automation is observable
- Work: Confirm the remote branch and peeled annotated tag point to the intended commits, then inspect the corresponding GitHub Actions run.
- Risks/open questions: Successful Git refs prove publication and workflow triggering intent, but not successful artifact production.
- Verify: `gh run list --repo caidaoli/CLIProxyAPI --limit 10`
